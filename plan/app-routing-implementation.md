## 1. 用户从哪里开始

以下为预期使用流程。用户连接 SSH 隧道，在主页「选项 → 代理方式」点进「应用分流」，选择「按应用分流」。点击「添加」选择本机的 Claude.app 和 ChatGPT.app，分别设为「全部走代理」。添加 Chrome 后，选择「仅指定域名走代理」，填入域名并应用。随后用 Chrome 访问两个不同目的地，即可在同一页核对蓝色「代理」和灰色「直连」。Safari 等未添加的应用继续使用本机网络。这里的“直连”指交回系统正常选路，用户已有的 VPN、系统服务和应用自行配置的代理仍可能影响最终出口。

设计以应用列表和规则编辑为主。最近连接只展示选中应用。主页承担状态摘要和导航。任意可识别的已安装 macOS 应用都可从选择器添加，首批端到端覆盖 Claude、ChatGPT 和 Chrome，并用未选的 Safari 做对照。应用规则属于这台 Mac；切换 SSH 服务器继续使用同一组规则。

## 2. 模式、策略与实际结果

| 代理方式 | 生效时的含义 | 主页摘要 |
|---|---|---|
| 仅本地代理 | 隧道提供本地 SOCKS5 和 HTTP 端口，由调用方自行选用 | 显示方式名，点击进入分流页 |
| 按应用分流 | 通过 macOS 透明代理扩展处理可归属的应用连接，按规则决定走向 | 显示方式名及已配置的应用数，含显式配置为直连的应用 |
| 全局代理 | 为所选网络服务启用现有系统 SOCKS；采用该系统代理的程序走隧道 | 显示方式名和网络服务，例如 Wi-Fi |

### 2.1 应用归属与判定顺序

1. 捕获面先排除 provider 自身、隧道进程和本应用实际中继端点；在隔离环境证明回环不递归。仅对可归属的出站连接评估应用规则。
2. 对受支持的签名应用，以团队标识与主程序精确签名标识作为稳定键，校验签名要求。路径用于定位，版本和代码哈希用于重新校验；移动、正常更新后仍能匹配同一身份。签名缺失、变更或身份冲突时停止自动关联并提示重新选择。
3. 通过系统提供的来源身份与审计令牌核实可执行文件，从已验证的应用包枚举联网 Helper 的精确签名身份并验证归属。更新后重建映射。相同团队、名称前缀、进程名或共享系统服务本身均不足以判定归属；只有能可靠归到单个 App 的系统代办连接才纳入。流的归属证据不足时交回系统，避免误接管其他 App。若独立观测发现目标 App 的必要流因此绕过隧道，该版本的全应用覆盖测试失败。不得用“未发现新事件”推断覆盖完整。详情可显示“经由 %@”及 Helper 名。
4. 先检查是否为已添加的 App，再按下述本地目的地与 DNS 分类，对外部目的地评估应用策略、主机名与协议，最后核对隧道可用性。未添加的 App 放行。首版域名来源限系统给出的连接主机名；无可靠域名时按下表。已知域名送入 SOCKS5 时使用域名地址类型并由隧道出口解析；仅有 IP 且需代理时使用相应 IPv4/IPv6 地址类型。应用此前的系统 DNS 查询仍可能发生。首版不解析 TLS 内容、不依赖 SNI、反查或共享 IP 来猜域名。

**本地目的地优先级（按应用分流模式）。** 选择“全部走代理”覆盖该 App 可归属的外部连接。以下例外让本机 MCP、开发服务器、局域网设备和链路发现保持可用。设置策略时在编辑器显示一行范围说明。

| 顺序 | 目的地如何认定 | 处理及边界 |
|---|---|---|
| 1 | 本机回环 127.0.0.0/8、::1、保留名称 localhost 及其子域；IPv4 映射的 IPv6 地址先规范化 | 交回系统。本应用内部中继另按来源与会话排除；普通本机端口不会因为连得上就被信任为中继。 |
| 2 | IPv4/IPv6 链路本地、局域广播及链路范围组播（含 mDNS）；本接口已知的直接相连单播前缀 | 交回系统。按接口索引、活动地址/路由判断；默认路由不算直连前缀。非链路范围组播不作本地豁免，需代理的 UDP 阻止。 |
| 3 | 私网 IPv4（RFC 1918）、IPv6 ULA、VPN 私网 | 经已确认的本地链路或具体私网路由（含 VPN 的非默认路由）到达则交回系统；不能确认时按外部目的地决策。外部 SOCKS 出口可独占另一同址私网，不因地址段本身永久豁免。 |
| 4 | 只有主机名、缺少已确认的本地目标地址 | 除 localhost 命名空间外，按外部域名规则判定，不为推测局域网身份额外解析。连接同时携带域名和明确本地端点时按前三行处理。 |

**DNS。** 系统解析器代办的查询使用现有系统/VPN DNS；无法可靠归属到单个 App 的系统查询不强行捕获。App 自发查询按**解析器端点**判定；不读取查询内容来决定这个连接的走向。指向本机、已确认 LAN/VPN 私网解析器或链路 mDNS 的查询先按上表。外部解析器行为如下，DNS 加密与否不改变端点规则。

| App 策略 | 外部解析器的 UDP/53、TCP/53、DoT、DoH |
|---|---|
| 全部直连 | 均交回系统。 |
| 全部走代理 | TCP/53、DoT 或基于 TCP 的 DoH 经 SSH；UDP/53、基于 QUIC 的 DoH 等 UDP 阻止。 |
| 仅指定域名走代理 | 解析器主机名命中时 TCP 代理、UDP 阻止；已知未命中则直连；仅有解析器 IP 时阻止。 |
| 仅指定域名直连 | 解析器主机名命中时直连；未命中或只有 IP 时 TCP 代理、UDP 阻止。 |

因此，按域名分流时可能要把解析器本身列入名单；DoH 使用 HTTPS，不依赖从内容识别它。可用域名的业务请求使用 SOCKS 域名地址类型请求出口解析；此行为与 App 先前自行解析是两个事件。

### 2.2 外部目的地运行时决策表

| 每 App 的连接策略 | 已知域名、命中 | 已知域名、未命中 | 只有 IP 或缺少可用域名 |
|---|---|---|---|
| 全部走代理 | 代理 | 代理 | 代理 |
| 全部直连 | 直连 | 直连 | 直连 |
| 仅指定域名走代理 | 代理 | 直连 | 阻止 |
| 仅指定域名直连 | 直连 | 代理 | 代理 |

表中“代理”对 TCP 表示建立 SOCKS5 中继，对 UDP 表示明确阻止，对未知或失效的隧道表示禁止直连回退。“直连”适用于 TCP 和 UDP。此规则覆盖所有 UDP 端口，包括 HTTP/3 的 UDP 443；协议自动回落到 TCP 取决于应用。白名单只放行能确认未命中的域名。仅有 IP 时，即使用户本想访问未列出的网站，也可能被阻止；这是防止白名单目标静默直连的明确取舍。黑名单仅允许可确认的例外直连。浏览器下载、聊天与语音分别验收。规则编辑器在两种域名策略下均展示未知域名行为；阻止记录给出具体原因。

- 域名输入一个主机名，包含其子域名。去除首尾空白和末尾 DNS 点，统一小写和 IDNA 表示。按完整标签边界匹配，例如 `chatgpt.com` 包含 `www.chatgpt.com`，不包含 `notchatgpt.com`。拒绝 URL、路径、端口、IP、通配符、空标签和无效 IDNA。界面就地提示，无效输入保留供修正。直接 IP 按表中最后一列处理；多个站点共享 CDN IP 时不倒推域名。
- SSH 连接路径描述“这台 Mac 怎样连到 SSH 服务器”。应用分流描述“谁的连接送入隧道”。两者可独立组合，入口、字段、日志均区分。服务器档案的自动、直连、通过代理设置继续负责前者。
- 「实际走向」来自扩展对具体连接的处理事件。代理握手并建立转发后记「代理」；已放行到系统记「直连」；明确拒绝记「已阻止」；代理尝试失败记「连接失败」。直连标记表示交还系统，不能据此断言远端连接成功。没有新事件时显示空态，不用配置推算历史走向。
- 产品边界：现有 SSH 动态转发承载 TCP。活动规则判定走代理的 UDP 明确阻止；允许直连的 UDP 交回系统。隧道断开、正在重连时，仍在工作的扩展阻止应走代理的新连接，并关闭失效中继。系统扩展未获批、被停用或失联时，界面显示分流未生效或状态未知，不能承诺此时仍阻止流量。系统 DNS、共享服务、VM 等归属边界见阶段一。

## 3. 应用分流页的操作细节

1. **页面和布局。** 导航位置在「连接」之后。页头放标题、未添加应用的默认行为、三段式代理方式。左栏放添加、搜索、应用图标、名称、已保存的策略和总数。右上是规则编辑器，右下是该 App 的最近连接。横向空间优先给右栏；在 840 × 580 默认窗口和 780 × 560 最小窗口，允许页头换行、域名标签折行及右栏纵向滚动，四个策略可从两列降为单列。列表和编辑区可独立滚动，保留窗口已有最小尺寸。
2. **添加应用。** 从系统应用选择器取图标、显示名和身份；同一身份重复选择时定位已有行。添加成功先以「全部直连」保存，使新应用的初始行为可预期；焦点转到右侧策略组。取消选择器回到原选中项。空列表显示添加入口；搜索无结果显示清除搜索。应用移动或更新按签名重新定位；无法确认显示「找不到应用」或「无法识别应用」，提供重新选择。名字相同的 App 用所在路径辅助辨认。
3. **编辑规则。** 四个选项单选。选择域名策略才展开「代理域名」或「直连域名」。每个模式保留各自的域名草稿，切换不把代理名单误当直连例外。标签上的 × 删除草稿项；点击「添加域名」出现单行输入，Return 添加，Esc 取消输入。每次应用发布完整策略。显式「全部直连」与从列表移除都会交回系统，前者保留应用及可恢复的名单。通过列表行的上下文菜单和键盘可移除规则。
4. **保存与离开。** 无修改时「应用更改」置灰。域名策略的空名单可编辑，但需至少一个域名才能应用，避免误选后整个 App 改变走向。应用中锁定重复提交。先校验并原子保存；写盘失败保留编辑草稿。写盘成功后，扩展活动时等待版本回执；超时保留已保存版本并读回活动版本，按第 5.1 节显示待生效或状态未知，允许重试。其他模式下允许编辑、保存，下次启用时应用（磁盘与扩展的版本按第 5.1 节协调）；选择应用、切页或关闭窗口前，对未保存更改提供应用、舍弃、继续编辑。将焦点放回触发操作或第一个无效字段。移除有规则的应用前显示其名称及恢复系统选路的影响。
5. **最近连接。** 列为「目标域名」「实际走向」「时间」。切换左侧选中项，表格同步过滤；最近一条在上。只有 IP 时显示地址和「仅有 IP」，有 IPv6 或长域名时支持完整阅读和复制。鼠标停留或 VoiceOver 可读出策略命中、默认走向、UDP 或隧道不可用等原因。颜色之外始终有文字，阻止和失败各用独立标签。配置的生效时间与历史记录分开；只对应用后的新连接使用新策略，现有已建立的连接可能需要在目标 App 中重新连接。
6. **活动与隐私。** 每个已配置 App 最近 50 条，在扩展内按 App 维护有界内存缓冲，窗口可见时批量刷新；主页面只显示能放下的数行，其余滚动。每条事件携带连接 ID、provider 会话 ID、判定时已确认的规则版本、时间、应用身份、目的主机或 IP、协议、判定与原因。页面在扩展确认新版本的时间插入分界线；详情及读屏显示版本，存量 HTTP/2 连接复用仍保留原版本与走向。按新请求条数推测已建立新连接会误判。移除应用、结束分流会话时清对应缓冲；退出后不恢复历史。未配置的 App 直接放行，不收集目标。域名例外配置需要持久化，访问历史不写规则文件、常规文本日志、macOS 统一日志、统计数据库或导出 CSV。宿主与扩展只记事件码、计数和错误类别；统一日志避免传入域名/IP 原值，含地址的底层错误先转译。

## 5. 模式切换、断线与迁移

| 条件 | 执行动作 | 用户所见 |
|---|---|---|
| 首次安装或从旧版升级 | 首次默认仅本地；旧 `systemSocksOn=true` 迁移为全局，false 为仅本地。仅在新字段缺失时迁移。保留端口、网络服务、服务器档案与 CLI 设置 | 原用户的选择可辨；升级本身不触发扩展授权 |
| 首次选择按应用分流 | 记录请求，加载规则，申请系统扩展批准，配置并启动 provider，验证控制通道和规则版本 | 依次显示准备、待批准、启用。拒绝或取消后保留已有可用方式；系统对话框使用 macOS 本地化文案 |
| 全局与按应用分流互换 | 按第 5.1 节串行切换并回读系统 SOCKS 与 provider。过渡期允许经验证的受控重叠，防止自环和保护空档 | 切换时显示进度。成功后全入口同步；失败恢复旧方式并核对，无法核对则明确显示状态未知 |
| 隧道断开、切换节点或重连 | 全局模式按隧道状态应用/收回本应用的 SOCKS；分流已启用时保持拦截，目的为代理的流失败，不转直连。再次连接探活后恢复 | 隧道标签可为「未连接」，分流的阻止原因另行展示；可选仅本地或全局以离开分流 |
| 主窗口关闭、睡眠唤醒、扩展中止 | 关闭窗口仅结束可视刷新。唤醒、扩展重启和重新打开时比对期望、活动会话和规则版本，重放最后成功配置 | 区分暂无记录、等候重连、扩展不可用；失联时不继续沿用绿色活动状态 |

### 5.1 切换事务与规则版本

- 所有入口共享单一事务。持久化事务 ID、目标方式、上次确认方式、网络服务与本应用持有的旧设置后，再修改系统。依次准备、等授权（如需）、接管/撤销、验证、提交。只在系统设置回读与 provider 会话/规则版本均符合目标后更新“当前生效”。陈旧回执按事务和会话 ID 丢弃。启动先协调未完成事务，再接受新请求。
- 准备、应用、验证、回滚的单步执行时限各 15 秒；审批由用户决定，等待期间允许取消或退出。取消使事务失效，晚到的批准不能启用分流。保持已确认的旧保护直至目标接管；无法验证时停留在旧方式或保持阻止，显示失败/未知。失败只回滚本应用持有且未被外部更改的设置。无确认的方式在菜单中不打勾。
- **切换不变量。** 新旧方式均要求代理的外部流，从请求切换到提交、取消或完成回滚，直达目标的连接数必须为零。允许连接短暂失败。全局方式的范围仍以实际采用系统 SOCKS 的应用为准；仅本地方式的显式代理连接仍须使用原端口。只在一端要求代理的流，在已核实的交接点改变走向。未知状态或 UI 显示“正在切换”都不能放宽验收条件。
- **交接顺序。** 全局转分流时先准备目标并在旧 SOCKS 仍有效时启用 provider 的过渡规则，确认共同受保护的流已能中继或明确阻止，再撤本应用的系统 SOCKS，确认目标规则。分流转全局时维持 provider 的中继/阻止，先建立并核实系统 SOCKS 的实际接管，再撤 provider。仅本地模式保留显式端口。外部设置变动或回滚遵循同一约束。受控重叠能否无自环、OS 客户端缓存是否导致直出均须 V5a 证明；无法建立安全交接的系统/方向保留原方式并拒绝该切换。不能靠设置回读、固定延时或假定客户端已刷新取得通过。
- **编辑规则**只影响新连接。**主动切换代理方式或退出**会关闭本应用接管的在途连接，切换前在存在中继时提示会中断上传、下载或流式会话，提供继续/取消；用户取消保留原会话。交回系统的既有连接不由本应用终止。修改端口或服务器时沿用隧道重建语义。
- 为规则分别维护“草稿、磁盘已保存版本、扩展已确认版本”。明确拒绝且读回旧版本时显示“新规则未获接受，原规则仍生效”。回执丢失时先读回：目标版本已活动即成功；已核实尚未应用显示“已保存，等待生效”；无法核实则保留已保存标记并显示“分流状态未知”。重连后按最新已保存版本幂等重放。离线保存与生效各有独立反馈，实际走向只来自具体连接事件。

### 5.2 宿主失联与恢复

**每条代理中继先证明对端属于当前隧道。** SOCKS 端口号、监听 PID 快照、TCP connect 成功及周期心跳均不足以证明本次已连接的对端归属。provider 必须在发送含目标域名/IP、端口或业务数据前，取得与本次连接和隧道会话绑定、无法由另一监听者复用的身份证据。第一阶段验证能否在目标系统绑定具体已连接的通道；若普通 TCP SOCKS 无可靠凭证，改走具备系统对端身份校验的宿主 IPC，由宿主提供与受控 SSH 传输绑定的中继。IPC 后再按端口号盲连仍属失败。首版不假定系统 ssh -D 支持会话口令。无法证明时阻止、记“隧道身份未验证”，重建后重新验证；不能用已开放的本地端口降级代理。V4 是正式中继的前置条件。

扩展在宿主存活、隧道断开时保留规则并阻止应代理的流。扩展通过带会话标识的心跳辨认宿主（每 5 秒，连续 3 次缺失，使用单调时钟）；醒来先协调状态。**检测到宿主失联且扩展仍在运行时，沿用最后确认的归属和规则：关闭现有代理中继，阻止所有应走代理的新流；明确直连和未选应用继续放行。** 不自动恢复无条件直连。宿主重启后重新握手，核实名下 SOCKS 监听和规则版本再允许代理。扩展本身已被系统终止时无法提供此保证。

主动退出先撤销本应用路由并回读系统，再退出；注销、强制结束、直接移入废纸篓等不可依赖宿主清理回调。恢复有两个入口：重新打开宿主协调或切换到仅本地；宿主无法运行时，用户从 macOS 系统设置停用本应用的网络配置/扩展。正常卸载先关闭分流并移除本应用配置，再移除程序。异常移除后，按各系统版本实测的手册路径清理。任何支持版本若无法在宿主缺失时解除拦截，阻止该版本分流发布。具体系统面板路径、强退后扩展是否存活均由第一阶段记录。

### 7.1 第一阶段 · 签名真机验证规程

**本阶段交付一份可复核的结果表。** 用最小签名宿主和 provider 原型验证判定、转发、拒绝及停用行为。只实现支撑实验的控制通道、可观测事件与中继。生产版产品实现和发布包在后续阶段复跑相同用例。离线模型、UI 模拟或直接在终端运行 curl 均不能替代桌面 App 测试。

**本轮真机进度。** macOS 27.0.1（26A434、arm64）上的 Apple Development 签名原型完成首次安装、用户允许、宿主与 provider 握手及扩展从 0.1/1 升级至 0.1/2。观察 `127.0.0.1:54843` 时，签名探针和另一进程各发一条 TCP 和一条 UDP 流。provider 记录 TCP/UDP 各 2 条，探针签名标识匹配和 audit token 存在各 2 条，其他来源 2 条。Docker 容器回显并记录了同样的四个标识。移除实验网络配置后 TCP/UDP 仍可回显。完整 V1 矩阵、V2 真实应用归属、SSH 中继和独立出口仍需验证。第 7.2 节的阶段门槛继续适用。[独立原型及真机验证记录](../prototypes/app-routing-phase1/README.md)

**Claude 桌面版初测。** 已安装的 Claude 6.6395.1 打开既有对话的观测窗内，Electron NetworkService Helper 的 TCP 活动走系统 HTTP 代理的回环端口 7890。多个 Electron Helper 共用签名标识，角色需要结合实际进程和套接字证据。独立合成请求证实当前 HTTP 代理和 TunnelProxy 的 SSH SOCKS 端口 1080 具有不同公网出口。未登录的独立 Claude 临时实例显式指定 SOCKS 后，NetworkService 启动时有 16 条 TCP 连接与 SSH 套接字配对并双向传输，主进程另有一条连接走 7890。随后 0.1/3 原型在专用回环桥的两轮显式代理实验中，通过 audit token 校验了 35 条 Claude Helper TCP 流。回环桥记录 33 次 SOCKS CONNECT 成功并双向传输，复测中有 15 条通过本机套接字逐连接核对至 SSH。负对照的单条 curl 流归为「其他来源」，Claude Helper 计数保持不变。实验配置已移除。扩展仅观察并交回流量。正式 Claude 会话的 SSH 出口、原型透明转发和 V2 的其余应用与业务动作尚未验收。[Claude 实测记录](../prototypes/app-routing-phase1/README.md#installed-claude-path-check)

**Claude 透明 CONNECT 原型。** 0.1/4 仅在实机批准的实验中匹配现有系统代理的 `127.0.0.1:7890` TCP，核对 audit token、进程树和已登记 SSH 套接字。独立 Claude 沿用系统代理，主进程 1 条和 Helper 9 条从实验允许的 HTTPS CONNECT 经原型、SSH SOCKS 双向传输。已登录实例也沿用现有系统配置，新对话操作窗口内有 2 条新 Helper 流经 SSH 双向传输，未观察到新的已验证主进程流。原有 3 条 NetworkService 到 7890 的连接同期继续传输。用户确认收到回复，现有元数据无法将单条消息或回复归到 SSH。未选进程的 curl 负对照成功且原型计数保持零。实验配置已移除。普通 HTTP、其他域名、既存连接和完整业务路径仍需验证。第 2.1 节的本地目的地规则与发布验收门槛继续适用。[透明 CONNECT 实测记录](../prototypes/app-routing-phase1/README.md#scoped-claude-transparent-connect-relay)

**已登录 Claude 冷启动复测。** 用户正常退出后，先验证旧进程和旧套接字消失，再以正常 profile 挂起启动并从规则 5 的零计数恢复。第一次新进程提前退出，退出机制未被系统记录证实。将重试进程放入独立进程组并保留启动器后，应用在测试及收尾均保持运行。第二次消息操作窗，Helper 经验证的 SSH 中继增加 2 条双向连接，流内累计新增发送 305,575 字节、接收 1,087,831 字节。独立网络元数据同时对上原系统代理 7890 的两条实际 TCP 连接，收尾同类套接字的进程签名核对为 `com.anthropic.claude-code`。这个后代签名不在目前主程序与 Helper 规则内，逐消息或整应用独占 SSH 尚未证明。0.1/5 最终拒绝类别为 24 条域名超出范围、3 条非 CONNECT HTTP，第二次消息窗新增 9 条域名超出范围。0.1/4 的 3 条拒绝没有历史分类记录。实验配置已移除，正式代理与 VPN 保持使用原配置。[冷启动复测详情](../prototypes/app-routing-phase1/README.md#logged-in-cold-start-reply-diagnostic)

**测试条件。** 使用隔离的 Mac 或可还原的测试用户及网络服务、专用 SSH 节点、测试账号。记录 OS build、CPU 架构、应用版本及实际签名标识、规则版本、代理端口、测试时间与网络拓扑。准备两个可区分的出口（本机网络与 SSH 出口），一个支持 IPv4/IPv6 及 HTTP/3 的受控站点；至少两个测试域名共用同一 IP，另备相似后缀名。先在关闭分流时验证站点可达、QUIC 确实协商成功、SSH 出口与直连出口可辨，再开始对照。对 IPv6 分三步预检：本机直达受控 IPv6 服务；SSH 节点实际能连接该服务的 IPv6 地址；经原生 SOCKS 的 IPv6 字面量和仅 AAAA 名称均到达受控服务并可核对 SSH 出口。记录每步 IP 族、来源地址及请求标识。出口仅 IPv4、无 IPv6 单栈设备或目的端无有效证据时，相应用例记「未测」，不能算拦截成功或归咎于扩展。未满足前置条件记「未测」，避免把无流量误判为拦截成功。

**证据口径。** 每次操作关联应用/Helper 身份、时间窗、目的地址/协议、扩展判定与独立出口观测。受控站点用唯一请求标识与服务端来源地址；真实 App 用按进程或连接元数据归属的系统观测，配合物理接口及实际 VPN/隧道接口的抓取和 SSH 出口侧连接记录。对“必须代理”的测试请求，以测试目标和时间窗为界，本机直达目标的连接数须为零，同时需有 SSH 出口成功证据或明确的阻止证据。抓到 SSH 服务器本身的数据是预期现象。共享 IP、VPN 封装或其他应用流量无法排除时标记「证据不足」。只保留判定所需的脱敏摘要、时间、计数及样例，避免采集聊天内容、令牌和无关用户的访问历史。

|---|---|---|
| V1 · 签名、安装及授权 | 在最低支持 macOS 14 和拟交付版本各用签名包执行首次安装、允许、拒绝、取消、重试、停用和升级。用 provider 实际收流、宿主握手及规则版本回读验证；另测用户在待批准时退出，之后再批准旧请求。 | 正确签名包安装后，只有活动会话且版本吻合才显示已启用。拒绝、取消、迟到批准均不意外接管网络，无关 App 连通。缺权限或无法复验的系统组合记未测；未通过的组合不进入分流发布范围。 |
| V2 · 谁真正发起连接 | 分别选取实际安装的 Claude、ChatGPT 和 Chrome。逐项执行冷启动、登录、对话/网页、流式响应、上传和下载，间隔操作以定位联网进程；查看适用的语音/WebRTC、系统 DNS、WebKit/共享服务、VM 或外部工具归属。列出“执行动作 → 进程及签名 → 可取得的来源证据 → 所属 App → 判定及出口”。用未选 Safari、同团队的另一款 App 做反例；移动应用、使用两个正常签名版本模拟升级，再用身份不同的测试包复核。 | 声明支持的动作中，所有观测到的目标 App 联网流都有可复查的归属及预期走向；应代理的流无直出。未选 App 维持基线出口，正常升级匹配原规则，身份改变提示重选。共享系统 DNS 单列其可见性和出口。任何必需业务流归属不明或误接管对照 App，均不能宣称该 App 版本“全部走代理”；在覆盖表和 UI 标出限制。 |
| V3 · 主机名、DNS 和 QUIC | Chrome 默认网络设置、开启安全 DNS 各跑一轮，QUIC 可用与关闭各测一次；控制站点同时提供列入/未列入、根/子域、相似后缀和同 IP 域名，再用仅 IP URL 对照。对白/黑名单各跑一次，分别测 TCP/UDP；另用两款目标桌面 App 记录真实操作中“有主机名条数 / 观测流总数”。通过测试 SOCKS 握手端核对域名/IPv4/IPv6 地址类型，以随机测试名在受控 DNS 观测出口解析；另记 App 自行发起的 DNS。 | 每种输入与第 2.2 节表格一致，白名单目标 TCP/QUIC 直达数均为零。已知准许直连的流符合系统出口；允许 TCP 代理的请求经 SSH 出口成功；未知域名须显示正确原因。只有已知域名代理时才要求 SOCKS 请求保留原主机名。若使用正常域名却大多只得到 IP，即使阻止策略正确，也须记录可用率与受影响操作；标准用例若无法使列出/未列出域名分别得到预期出口，则该 App/版本的域名分流不通过，只可独立评估全 App 策略。 |
| V3 补测 · 本机、局域网和 DNS | 用测试 App 分别访问 localhost/IPv4/IPv6 回环、链路本地、已确认私网路由及同类地址但无具体路由的目标，测试链路 mDNS；在四种策略下，对受控本地与外部解析器分别发 UDP/53、TCP/53、DoT、DoH（TCP/QUIC），分别提供已知命中、未命中和仅 IP 的解析器端点；系统代办 DNS 单列。 | 本地服务仍可达、SSH 侧无本地目标流。其余逐格对照第 2.1–2.2 节，从解析器侧观测查询来源或明确阻止事件。若系统未交付本地流，以本地响应与独立出口观测验收，不伪造“实际走向”事件。 |
| V3 补测 · 连接复用 | 在受控 HTTP/2 长连接上传输，切换一次规则版本，继续使用同一连接，再显式建立全新连接请求同一域名。两代会话使用测试事件与服务端连接标识交叉核对。 | 旧连接沿用旧出口与旧版本，新连接从新版本确认后按新规则走；拒绝/未确认的版本不成为事件来源。原型只需两份内存规则和事件输出；时间分界及读屏由 V8b 验收。 |
| V4 · 隧道、宿主和扩展分别消失 | 目标 App 设置为全部走代理，另开 Safari 对照。依次手动断开 SSH、停止上游、强退宿主（分别保留/停止 SSH）、强停扩展、睡眠唤醒、重新打开宿主、正常退出。持续对测试站点发新请求并保持一条中继。以中继不可用时仍有正常宿主心跳为对照，分别记录最后一次心跳、判为失联、阻止和恢复的时间。再从可还原安装测试正常卸载及意外移除，关闭宿主后按对应 OS 的系统设置步骤解除分流并重启。 | 仍工作的扩展在隧道故障时阻止应代理流；宿主失联按第 5.2 节时限收口，直连对照能联网。区分强退后扩展是否继续运行，另行强停扩展覆盖其缺席的情形。重新打开先协调再处理新请求；正常退出及正常卸载后无活动接管。意外移除即使有残留，也能在宿主缺失时用记录的系统步骤恢复，重启后无意外复启。无法解除拦截或确认恢复时，阻止该系统版本发布。 |
| V4 补测 · SOCKS 对端归属 | 在受控测试夹具中先证实当前 SSH 会话可转发，再结束该会话并在同一测试端口替换为空白测试接收端；覆盖心跳更新前、验证与发送之间更换对端、重连及重新使用相同端口。用无敏感内容的测试目标和标识检查接收端，随后恢复合法会话。 | 每条连接均有当前会话绑定的凭证；替代接收端收到的测试目标地址、域名和业务字节均为零；扩展报阻止且无直出。恢复后仅新验证的会话可转发。原型没能证明任一环节，正式中继保持待验证。 |
| V5a · 原型交接 | 在隔离网络服务上双向切换全局/分流，切换前、中、后持续新建带唯一标识的受控请求；分别延迟目标就绪、取消、注入启用失败、回滚和晚到的简单会话回执。以直连对照证实观测链有效，同时检查 provider 与 SSH 自身出站。 | 对两边都要求代理的每个请求，有代理出口或明确失败证据；本机直达目标为零，自环为零。旧回执不改变新会话。覆盖接管边界且能复查失败，不能关联的请求记证据不足；只要有一次直出即失败，该方向不可开放。 |
| V6 · 平台与其他网络配置 | 列出可运行组合：macOS 14、15、26 及本次拟交付版本，Apple 芯片和仍支持该系统的 Intel。记录实机/未测/硬件不适用。使用 IPv4、双栈、IPv6 单栈，分别在无 VPN、已有系统代理、使用测试 VPN 或另一透明代理时测代理/直连及启停恢复；用 VPN 的实际接口和远端观测佐证结果。 | 各声明支持的组合里，独立观测与预期一致，未选 App 保留原出口，退出后第三方配置和连接正常。不能可靠共存时给出兼容限制，不自动停用第三方服务。无法取得的系统/架构记未测，不能当作已兼容。 |
| V7a · 原型中继与日志 | 同设备、源站及 SSH 链路，直接经本地 SOCKS 作基线，交替运行至少 3 轮下载和短请求，记录吞吐中位数、建连 p95、CPU 与 RSS；32 并发跑 10 分钟，两轮后静置。以合成域名检查宿主和扩展统一日志、原型自定义诊断。 | 吞吐至少基线 80%，建连 p95 额外耗时至多 50 ms；基线抖动过大则重测。无死锁、无残留中继；第二轮静置 RSS 至多为第一轮的 110% + 5 MiB。日志与诊断中合成域名命中为零。 |
| V8a · 系统恢复与协议影响 | 用签名原型在实际系统面板批准、拒绝、撤销。宿主缺失时分别在中英文系统按记录步骤解除拦截。目标 App 支持语音时与未启用原型的基线比较，记录协议及是否回落。 | 用户无需运行宿主即可解除本应用接管，重启后不意外复启；记录对应系统版本的实际路径。语音查询输出有可核对的回落、阻止或受限原因；无基线记未测。正式页面和 VoiceOver 交给 V8b。 |

### 7.2 后续产品验收与开工条件

**1.2.0 实现记录。** 正式宿主集成独立签名扩展 `com.xwkj.tunnelproxy.approuting`。应用分流规则匹配目标应用新建的直接 TCP/UDP 连接，使用系统连接元数据判断域名，通过 audit token 验证桌面应用及其签名 Helper。Claude Code 还须有已验证的 Claude 桌面祖先。需要代理的 TCP 连接在发送目标前核对本次 SOCKS 连接确由正式宿主的 SSH 子进程接受，应走代理的 UDP 或未验证的隧道连接会阻止。普通本机回环与可辨认的本地网段按本地优先规则处理，未归属流和明确直连均交回系统。应用分流页、主页、菜单与菜单栏弹窗已接入共享模式和中英文字段。直接在全局模式与应用分流之间切换需要尚未取得的安全交接证据，因此保留旧模式，并由用户显式选择仅本地后再切换。此版本只记录构建、签名和静态证据，产品包的安装、各系统的实际收流、出口、断线恢复及共享系统代办归属仍须按以下规程复验。

| 产品用例 / 阶段 | 如何验收 | 通过标准 |
|---|---|---|
| V5b · 阶段 2–3 控制器与中继 | 六个切换方向，五个状态注入故障并重启；重复全局/分流互切 50 次，包含迟到回执、端口变化、第三方系统代理、长下载与流式会话，接受/取消切换。持续使用 V5a 独立出口探针。 | 所有有交集的流零直出；一次事务至多一次提交，重启能恢复或明确未知；旧回执、外部修改不会被误用；同意中断可重连、取消不中断。端口变更只在约定时机生效，每条新中继通过 V4 的身份检查。 |
| V7b · 阶段 3–4 数据留存 | 注入超过 50 条选中应用事件和未选对照，在产品宿主/扩展日志、统计、CSV、诊断与规则文件中搜索独立的测试标记；退出重开。产品包复跑 V7a 性能基线。 | 每 App 最多留 50 条，未选 App 的目标记录为零；只有显式配置的域名可以出现在规则文件，访问历史不进入任何持久化输出，结束会话后清空。正式中继满足 V7a 或明确限制，隐私失败阻止发布。 |
| V8b · 阶段 4 界面及本地化 | 两种语言在主页、菜单栏、迷你窗和分流页验证各状态、计数、Helper、仅 IP、策略原因和 UDP 说明。复跑 V3 长连接用例，检查扩展确认新版本前后、会话重建和系统时钟变化。 | 状态与第 5.3 节相符，0/1/多数量准确，读屏完整、无裸 key；确认后出现生效时间分界，旧流不重标，详情与读屏可辨各自规则版本。系统恢复文案使用 V8a 在对应版本验证过的路径。 |

**执行顺序。** 本计划定稿即可以独立原型启动第一阶段；模型与模拟 UI 可并行。每项记录环境、复现动作、预期、独立观测、证据编号、通过/失败/未测和影响范围。进入阶段 3 的条件为目标系统 V1、V4（含对端身份）、V5a 通过，并对拟支持的 App/策略取得 V2、V3 证据。V5b 是正式转发定型条件，V7b、V8b 是对应产品验收，不要求第一阶段具备持久事务、统计或成品界面。V6、V7a、V8a 确定平台、性能及功能适用范围；产品发布还须完成对应范围的第 8 节与发布包复验。任何需要代理的核心业务出现未解释直出，即保留该目标未完成。

宿主用途描述 `NSSystemExtensionUsageDescription` 的 English 为 **Tunnel Proxy uses a network extension to route connections from the apps you choose through your SSH tunnel.** 简体中文为 **Tunnel Proxy 使用网络扩展，将所选应用的连接按规则转发到 SSH 隧道。** 由系统生成的授权标题和按钮随 macOS 版本变化，手册引用实际发布版本的界面。接口依据可对照 [Apple 透明代理](https://developer.apple.com/documentation/networkextension/netransparentproxyprovider)、[连接来源](https://developer.apple.com/documentation/networkextension/neappproxyflow/metadata) 和 [目的主机名的可用条件](https://developer.apple.com/documentation/networkextension/neappproxyflow/remotehostname)。
